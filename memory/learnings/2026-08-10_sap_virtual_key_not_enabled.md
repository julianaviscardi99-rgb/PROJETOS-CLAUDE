# Aprendizado: SAP GUI Scripting — evitar SendVKey para navegação "voltar"

**O que aconteceu:** em `atualizar_ksb1_gui.py`, depois de exportar um arquivo da KSB1, o script tentava voltar para a tela de seleção com `session.FindById("wnd[0]").SendVKey(3)` (F3). Isso falhava intermitentemente com o erro do SAP `(-2147352567, 'Exception occurred.', (617, 'SAP Frontend Server', 'The virtual key is not enabled.', ...))`, porque nem toda tela tem a tecla F3 habilitada no momento exato em que o script tenta usá-la (ex: logo após fechar um diálogo de exportação). Isso travava a extração no meio de um loop com múltiplas extrações sequenciais (Gestoriais + Sem Agrupamento) — só a primeira rodava.

**Primeira correção (insuficiente):** trocar `SendVKey(3)` por reabrir a transação do zero via `/nKSB1` no campo de comando. Isso resolveu o crash, mas criou um bug novo: como `session.Info.Transaction` continua sendo `"KSB1"` tanto na tela de seleção quanto na tela de resultados, a checagem `if session.Info.Transaction != "KSB1"` pulava a reabertura — a segunda extração tentava preencher campos da tela de seleção (`ctxtP_KOKRS` etc.) que não existem na tela de resultados, gerando `"The control could not be found by id"`.

**Correção final (a que ficou):** em vez de `SendVKey` OU de reabrir a transação do zero, clicar direto no botão "Voltar" da toolbar (`session.FindById("wnd[0]/tbar[0]/btn[3]").Press()` — a seta verde). Diferença chave: `SendVKey(3)` simula a tecla F3, que o SAP pode reportar como desabilitada dependendo do estado da tela; pressionar o botão da toolbar (mesmo ícone, mesma função) evita essa checagem de tecla e funciona de forma confiável. Também é melhor do que reabrir via `/nKSB1`, porque mantém os campos da tela de seleção já preenchidos (só precisa trocar o agrupamento), reproduzindo o fluxo manual real da usuária: apertar a seta verde para voltar, apagar o agrupamento "Gestoriais" e rodar de novo para gerar o "Sem Agrupamento".

**Regra geral para scripts de SAP GUI Scripting neste projeto:** para navegação "voltar" entre passos de um script (especialmente em loops com múltiplas execuções), preferir `session.FindById("wnd[0]/tbar[0]/btn[3]").Press()` (botão "Voltar") em vez de `SendVKey(3)` (mesma tecla simulada, mas sujeita a ficar "desabilitada" conforme o estado da tela) e em vez de reabrir a transação do zero via `/n<transação>` (que limpa os campos e exige preencher tudo de novo — só usar isso como fallback se o botão "Voltar" não levar à tela esperada). `SendVKey` de execução (F8 = Executar, Enter = 0) direto na tela de seleção continua ok; o risco é especificamente em teclas de navegação/retorno.
